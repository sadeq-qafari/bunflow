## ۱. برنامه چه کاری انجام می‌دهد؟

BunFlow به شما اجازه می‌دهد بدون نوشتن کد، ساختار اطلاعات خود را با فرم‌ها تعریف کنید و سپس رکوردهای آن فرم‌ها را ثبت، جستجو و مدیریت کنید. برای مثال می‌توانید فرم «مخاطبان»، «کالاها»، «پروژه‌ها» یا «سفارش‌ها» بسازید.

امکانات اصلی نسخهٔ مستقل عبارت‌اند از:

- طراحی بصری فرم با فیلدهای متنی، عددی، انتخابی، چندانتخابی، مبلغ، تاریخ، زمان، ایمیل و بله/خیر؛
- تعیین عرض و ترتیب فیلدها و مشاهدهٔ پیش‌نمایش؛
- ثبت، ویرایش، حذف و مرور اطلاعات در جدول؛
- ارتباط بین فرم‌ها و تعریف لیست‌های ثابت انتخاب؛
- جستجو در یک فرم یا همهٔ فرم‌ها؛
- خروجی Excel و ورود مرحله‌ای اطلاعات از Excel؛
- نگهداری اطلاعات در SQLite و انتقال تعریف‌ها و داده‌ها با JSON از طریق API.

این نسخه یک حساب مدیر محلی و یک فضای کاری دارد. سامانهٔ کاربران متعدد، نقش‌های مستقل، سرویس ابری و همگام‌سازی خودکار بین رایانه‌ها در آن پیاده‌سازی نشده است. بعد از دریافت فایل اجرایی، استفادهٔ معمول از برنامه به اینترنت نیاز ندارد؛ نمایش رابط همچنان از طریق مرورگر انجام می‌شود.

## ۲. اصطلاحات و ساختار اطلاعات

| اصطلاح | معنی | مثال |
| --- | --- | --- |
| فضای کاری | مجموعهٔ فرم‌ها، لیست‌ها و رکوردهای یک پایگاه داده | اطلاعات یک دفتر |
| فرم | ساختار یک نوع اطلاعات؛ مشابه یک جدول با ستون‌های مشخص | مخاطبان |
| فیلد | یک ویژگی از اطلاعات فرم | نام کامل، تلفن، شهر |
| رکورد | یک مورد ثبت‌شده در فرم | اطلاعات یک مخاطب |
| لیست انتخاب | مجموعهٔ گزینه‌های از پیش تعیین‌شده با عنوان و مقدار | وضعیت: فعال، غیرفعال |
| فرم مرتبط | فرمی که رکوردهای آن در فرم دیگر انتخاب می‌شوند | شهرها در فرم مخاطبان |
| نام انگلیسی | شناسهٔ فنی فرم یا فیلد | `contacts`، `full_name` |
| عنوان | نامی که کاربر در رابط می‌بیند | مخاطبان، نام کامل |
| تعریف فرم | مشخصات، فیلدها، روابط و چیدمان؛ بدون الزام به داشتن رکورد | الگوی فرم مخاطبان |

**تفاوت عنوان و نام انگلیسی:** عنوان می‌تواند فارسی باشد. نام انگلیسی برای شناسایی فرم و فیلد در برنامه استفاده می‌شود؛ آن را کوتاه، روشن و ثابت انتخاب کنید.

**تفاوت فرم و رکورد:** ساخت فرم، اطلاعات واقعی را ثبت نمی‌کند. ابتدا فرم را ذخیره می‌کنید و سپس برای هر مورد، یک رکورد جداگانه می‌سازید.

<a id="run"></a>
## ۳. دریافت و اجرای برنامه

### ۳.۱. دریافت نسخهٔ آماده

1. صفحهٔ [انتشارهای BunFlow](https://github.com/sadeq-qafari/bunflow/releases) را باز کنید.
2. انتشار موردنظر را انتخاب کنید.
3. در بخش **Assets**، برای ویندوز فایل `flow.exe` و برای لینوکس x64 فایل `flow` را دریافت کنید.
4. فایل را در یک پوشهٔ ثابت و قابل دسترس قرار دهید.

فایل‌های **Source code** کد منبع هستند؛ برای اجرای ساده، فایل اجرایی مخصوص سیستم‌عامل را دریافت کنید. این دو خروجی برای معماری x64 ساخته می‌شوند. نسخهٔ ARM یا macOS در گردش ساخت فعلی مخزن ارائه نمی‌شود.

به نصب Bun، Node.js، npm، SQL Server یا وب‌سرور جداگانه نیاز ندارید. برای ساخت از کد منبع، [راهنمای فنی نسخهٔ مستقل](../standalone/README.md) را ببینید.

### ۳.۲. اجرای ویندوز

برای مشاهدهٔ پیام‌های اجرا و رمز اولیه، PowerShell را در پوشهٔ فایل باز کنید:

```powershell
.\flow.exe
```

سپس در مرورگر باز کنید:

```text
http://127.0.0.1:5000
```

تا زمانی که برنامه را استفاده می‌کنید، پنجرهٔ اجرای آن را باز نگه دارید. بستن این پنجره، سرویس محلی را متوقف می‌کند. بستن مرورگر به‌تنهایی برنامهٔ اجرایی را متوقف نمی‌کند.

برای تعیین رمز و محل اطلاعات در **اولین اجرا**:

```powershell
$env:FLOW_ADMIN_PASSWORD = 'Replace-With-Your-Own-Password'
.\flow.exe --data-dir 'C:\BunFlow\data' --port 5000
Remove-Item Env:FLOW_ADMIN_PASSWORD
```

رمز نمونه را با رمز دلخواه خود جایگزین کنید. دستور آخر بعد از پایان اجرای برنامه قابل اجراست و متغیر را از همان نشست PowerShell پاک می‌کند. اگر پوشهٔ اطلاعات قبلاً پایگاه داده داشته باشد، این متغیر رمز آن حساب را تغییر نمی‌دهد.

### ۳.۳. اجرای لینوکس

ترمینال را در پوشهٔ فایل باز کنید:

```sh
chmod +x flow
./flow
```

نشانی مرورگر همان `http://127.0.0.1:5000` است. برای تعیین رمز و پوشه در اولین اجرا:

```sh
FLOW_ADMIN_PASSWORD='Replace-With-Your-Own-Password' ./flow --data-dir ./flow-data --port 5000
```

مسیر نسبی `./flow-data` نسبت به پوشه‌ای محاسبه می‌شود که دستور را از آن اجرا کرده‌اید. برای جلوگیری از ایجاد ناخواستهٔ چند پایگاه داده، می‌توانید مسیر کامل بدهید.

### ۳.۴. گزینه‌های اجرا و محل اطلاعات

| گزینه | کاربرد | مقدار پیش‌فرض |
| --- | --- | --- |
| `--port` | درگاه سرویس | `5000` |
| `--host` | نشانی‌ای که سرویس روی آن گوش می‌دهد | `127.0.0.1` |
| `--data-dir` | پوشهٔ پایگاه داده | `.local/share/flow` زیر پوشهٔ خانگی کاربر |
| `--help` | نمایش راهنمای خط فرمان | — |
| `FLOW_PORT` | جایگزین محیطی درگاه | در نبود `--port` |
| `FLOW_DATA_DIR` | جایگزین محیطی پوشهٔ اطلاعات | در نبود `--data-dir` |
| `FLOW_ADMIN_PASSWORD` | رمز ایجاد حساب در اولین اجرا | در نبود آن، رمز تصادفی ساخته می‌شود |

نام فایل پایگاه داده `flow.sqlite` است. در ویندوز، مسیر پیش‌فرض زیر پوشهٔ خانگی همان حساب ویندوز قرار می‌گیرد؛ به پوشهٔ فایل اجرایی وابسته نیست. تعیین صریح `--data-dir` پیدا کردن و پشتیبان‌گیری اطلاعات را ساده‌تر می‌کند.

برای توقف، در ترمینال `Ctrl+C` بزنید. برای اجرای بعدی، همان فایل را با **همان پوشهٔ اطلاعات** اجرا کنید. برنامه یک سرویس خودکار سیستم‌عامل یا برنامهٔ نصب‌شده در سینی سیستم نیست.

## ۴. ورود، تغییر رمز و خروج

### ۴.۱. ورود اولیه

1. فایل اجرایی را اجرا کنید.
2. در اولین اجرا، پیام `Initial admin password` در ترمینال دیده می‌شود؛ رمز پس از آن را در جای امن نگه دارید. این پیام فقط هنگام ایجاد حساب اولیه چاپ می‌شود.
3. صفحهٔ محلی برنامه را باز کنید.
4. در «نام کاربری»، `admin` را وارد کنید.
5. در «کلمه عبور»، رمز اولیه یا رمزی را که خودتان تعیین کرده‌اید وارد کنید.
6. روی «ورود» کلیک کنید.

رمز باید حداقل **۸ نویسه** داشته باشد. اگر اطلاعات تازه و خالی دیده می‌شود، ابتدا مطمئن شوید برنامه را با پوشهٔ درست اطلاعات اجرا کرده‌اید.

### ۴.۲. تغییر رمز

1. از بالای صفحه، روی بخش پروفایل مدیر کلیک کنید.
2. گزینهٔ تغییر کلمه عبور را انتخاب کنید.
3. رمز فعلی، رمز جدید و تکرار رمز جدید را وارد کنید.
4. روی «ثبت» کلیک کنید.
5. پس از تغییر، دوباره با رمز جدید وارد شوید؛ نشست‌های قبلی در سمت سرویس باطل می‌شوند.

ممکن است متن راهنمای قدیمی پنجره حداقل ۶ نویسه را ذکر کند؛ الزام واقعی نسخهٔ مستقل **۸ نویسه** است. این پنجره در کد فعلی برای ورودی‌های رمز پوشانندگی استاندارد ندارد؛ هنگام تایپ به مشاهده‌پذیری صفحه توجه کنید.

### ۴.۳. خروج و رمز فراموش‌شده

از منوی پروفایل، «خروج» را انتخاب کنید. خروج از رابط، اطلاعات ورود ذخیره‌شده در همان مرورگر را پاک می‌کند؛ آن را معادل توقف سرویس یا خروج از همهٔ دستگاه‌ها ندانید.

بازیابی رمز با ایمیل یا دکمهٔ «فراموشی رمز» در نسخهٔ مستقل وجود ندارد. تعیین دوبارهٔ `FLOW_ADMIN_PASSWORD`، رمز پایگاه دادهٔ موجود را بازنشانی نمی‌کند. در صورت فراموشی، پایگاه داده را حذف نکنید؛ از آن پشتیبان بگیرید و برای بازیابی حساب به نگهدارندهٔ برنامه مراجعه کنید.

## ۵. آشنایی با داشبورد و مسیرها

بعد از ورود، صفحهٔ «داده‌های شما» نمایش داده می‌شود:

- **ساخت فرم:** ورود به طراح فرم جدید؛
- **جستجو در داده‌ها:** جستجوی رکوردها در همهٔ فرم‌ها؛
- **فرم‌های داده:** کارت‌های فرم‌های موجود و تعداد فیلدهای هر فرم؛
- **پیدا کردن فرم:** فیلتر کارت‌ها بر اساس عنوان، نام انگلیسی یا توضیحات؛
- **مشاهده رکوردها:** باز کردن جدول اطلاعات همان فرم؛
- **آیکن تنظیمات کارت:** ویرایش تعریف فرم؛
- **منوی کناری:** دسترسی به نمای کلی، ساخت فرم و فرم‌های موجود.

فیلتر «پیدا کردن فرم» فقط فرم‌ها را پیدا می‌کند؛ برای پیدا کردن مقدار داخل رکوردها، از جستجوی داده‌ها استفاده کنید. در موبایل، منوی کناری با دکمهٔ منو باز می‌شود. در طراح فرم، منوی کناری اصلی پنهان است تا فضای بیشتری در اختیار طراحی قرار گیرد.

مسیرهای زیر بعد از نشانی پایهٔ برنامه قرار می‌گیرند. مثلاً `/flow` یعنی `http://127.0.0.1:5000/flow`.

| صفحه | مسیر |
| --- | --- |
| داشبورد | `/flow` |
| طراح فرم جدید | `/service/flow/form/info` |
| فهرست مدیریتی فرم‌ها | `/service/flow/form` |
| فهرست لیست‌های انتخاب | `/service/flow/lookup` |
| ساخت لیست انتخاب | `/service/flow/lookup/info` |
| جدول یک فرم | `/flow/contacts` برای فرم با نام `contacts` |
| ثبت رکورد جدید | `/flow/contacts/0` |
| ورود Excel | `/flow/import/contacts` |

اگر مسیر مدیریتی در منوی فعلی دیده نمی‌شود، می‌توانید نشانی آن را مستقیماً در مرورگر باز کنید. نام `contacts` در مثال‌ها را با نام انگلیسی فرم خود جایگزین کنید.

## ۶. آموزش سریع: ساخت فرم مخاطبان

### گام اول: ساخت فرم

1. از داشبورد روی «ساخت فرم» بزنید.
2. در پنل «مشخصات فرم»، عنوان را «مخاطبان» و نام انگلیسی را `contacts` قرار دهید.
3. در توضیحات بنویسید: «اطلاعات تماس اشخاص».
4. گزینه‌های ثبت، ویرایش و حذف رکورد را برای این مثال روشن نگه دارید.

### گام دوم: افزودن فیلدها

از پنل «افزودن فیلد»، هر فیلد را اضافه کنید و سپس مشخصات آن را در پنل تنظیمات وارد کنید:

| نوع فیلد | عنوان | نام انگلیسی | نوع داده | عرض | ضروری؟ |
| --- | --- | --- | --- | --- | --- |
| متن | نام کامل | `full_name` | `string` | تمام ردیف | بله |
| متن | تلفن | `phone` | `string` | نصف ردیف | خیر |
| متن | شهر | `city` | `string` | نصف ردیف | خیر |
| متن بلند | یادداشت | `notes` | `string` یا `text` | تمام ردیف | خیر |

تلفن را **متن** تعریف کنید؛ فیلد عددی صفر ابتدای شماره را حفظ نمی‌کند و برای شماره تلفن مناسب نیست.

### گام سوم: پیش‌نمایش و ذخیره

1. ترتیب را نام کامل، تلفن، شهر، یادداشت قرار دهید.
2. روی «پیش‌نمایش» بزنید و چیدمان را بررسی کنید.
3. به حالت «طراحی» برگردید.
4. روی «ذخیره فرم» بزنید و منتظر پیام موفقیت بمانید.
5. از «بازگشت» به داشبورد بروید؛ کارت مخاطبان نمایش داده می‌شود.

### گام چهارم: ثبت اولین مخاطب

1. «مشاهده رکوردها» را باز کنید.
2. «افزودن رکورد» را بزنید.
3. نام کامل «علی رضایی»، تلفن `09151234567` و شهر «مشهد» را وارد کنید.
4. «ثبت رکورد» را بزنید.
5. جدول را باز کنید و وجود رکورد را بررسی کنید.
6. برای تمرین، آن را با آیکن ویرایش باز کنید، یادداشت را تغییر دهید و «ذخیره تغییرات» بزنید.

این چهار گام، چرخهٔ اصلی کار با برنامه‌اند: **تعریف فرم → ذخیرهٔ فرم → ورود اطلاعات → مرور و مدیریت رکوردها**.

## ۷. طراحی فرم و تنظیم مشخصات

### ۷.۱. سه بخش طراح

| بخش | جایگاه در دسکتاپ | کاربرد |
| --- | --- | --- |
| افزودن فیلد | سمت راست | انتخاب نوع فیلد و جستجوی ابزارها |
| چیدمان فرم | وسط | انتخاب، ترتیب‌دهی و پیش‌نمایش فیلدها |
| مشخصات/تنظیمات | سمت چپ | ویرایش فرم، فیلد انتخاب‌شده یا عملیات |

با کلیک روی یک نوع فیلد، فیلد جدید اضافه و انتخاب می‌شود. با کلیک روی کادر هر فیلد، تنظیمات همان فیلد باز می‌شود. برای برگشت به مشخصات فرم، دکمهٔ «مشخصات فرم» زیر چیدمان یا دکمهٔ بستن تنظیمات فیلد را بزنید.

کادرهای روی بوم طراحی برای نمایش هستند؛ مقدار واقعی یک رکورد را در صفحهٔ ثبت رکورد وارد کنید.

### ۷.۲. مشخصات فرم

- **عنوان فرم:** نام نمایشی فارسی، مانند «سفارش‌ها»؛
- **نام انگلیسی:** شناسه‌ای مانند `orders`؛
- **توضیحات:** توضیح کاربرد فرم که در کارت داشبورد هم دیده می‌شود؛
- **امکان ثبت رکورد:** اجازهٔ ایجاد رکورد جدید؛
- **امکان ویرایش رکورد:** اجازهٔ ذخیرهٔ تغییرات رکورد موجود؛
- **امکان حذف رکورد:** اجازهٔ حذف رکورد؛
- **فرم فعال:** ویژگی وضعیت که در تعریف ذخیره می‌شود؛ در نسخهٔ فعلی نباید آن را ابزار قطعی مسدود کردن دسترسی تلقی کرد.

ممکن است دکمهٔ ثبت یا حذف در رابط دیده شود، اما وقتی مجوز مربوط خاموش است، سرویس عملیات را رد می‌کند. این گزینه‌ها مجوز یک کاربر خاص نیستند؛ رفتار کلی همان فرم را تعیین می‌کنند.

### ۷.۳. قواعد نام انگلیسی

نام انگلیسی فرم و فیلد باید:

1. با حرف انگلیسی شروع شود؛
2. فقط شامل حروف انگلیسی، ارقام انگلیسی و `_` باشد؛
3. حداکثر ۶۴ نویسه داشته باشد؛
4. برای فرم‌ها در فضای کاری و برای فیلدها در همان فرم تکراری نباشد؛ تفاوت بزرگی و کوچکی حروف، نام جدید ایجاد نمی‌کند.

نمونه‌های درست: `contacts`، `order_items`، `phone2`.

نمونه‌های نادرست: `2phone`، `full name`، `نام`، `full-name`.

برای نام فیلد، نام‌های رزروشدهٔ `id`، `tenantid`، `createdat`، `modifiedat`، `createdby` و `modifiedby` را استفاده نکنید.

### ۷.۴. ذخیره و خروج از طراح

ذخیرهٔ فرم با دکمهٔ «ذخیره فرم» انجام می‌شود. ذخیرهٔ خودکار یا بازیابی تضمین‌شدهٔ تغییرات ذخیره‌نشده وجود ندارد. پیش از بازگشت، بستن مرورگر، تازه‌سازی صفحه یا خروج از برنامه، فرم را ذخیره کنید.

اگر پیام خطا آمد، فرم را ذخیره‌شده فرض نکنید. عنوان، نام انگلیسی و نوع دادهٔ فیلدهای مشخص‌شده را اصلاح کنید و دوباره ذخیره کنید. برای ویرایش فرم موجود، از آیکن تنظیمات کارت آن در داشبورد استفاده کنید.

## ۸. انواع فیلد و نوع داده

**نوع فیلد** ظاهر ورودی را تعیین می‌کند؛ **نوع داده** تعیین می‌کند چه مقداری ذخیره و اعتبارسنجی شود. گزینه‌های نوع داده، متناسب با نوع فیلد انتخابی نمایش داده می‌شوند.

| ابزار | کاربرد معمول | نکتهٔ استفاده |
| --- | --- | --- |
| متن | نام، کد، تلفن، شناسه | برای صفر ابتدایی و کدهای دارای حروف مناسب است |
| عدد | تعداد، سن، اندازه | `int` برای عدد صحیح؛ انواع اعشاری برای مقدار غیرصحیح |
| متن بلند | آدرس یا توضیحات چندخطی | معمولاً عرض تمام ردیف مناسب‌تر است |
| انتخاب | یک گزینه از لیست یا یک رکورد مرتبط | باید لیست انتخاب یا ارتباط فرم تنظیم شود |
| انتخاب چندگانه | چند گزینه یا چند رکورد مرتبط | مقدارها به‌صورت مجموعهٔ انتخاب‌ها ذخیره می‌شوند |
| بله / خیر | تأیید، وضعیت دوحالتی | مقدار منطقی؛ صفر/یک و برخی نمایش‌های متنی نیز در ورود داده پذیرفته می‌شوند |
| مبلغ | مقدار مالی | واحد پول و ریال/تومان را در عنوان مشخص کنید؛ تبدیل خودکار ارز یا واحد ندارد |
| تاریخ | تاریخ یک رویداد | ورودی تاریخ مرورگر؛ تقویم جلالی اختصاصی برای این فیلد پیاده‌سازی نشده است |
| زمان | ساعت یک رویداد | قالب ورودی زمان مرورگر، معمولاً `HH:mm` |
| ایمیل | نشانی ایمیل | شکل ورودی ایمیل؛ ذخیرهٔ موفق را تضمین اعتبار واقعی نشانی ندانید |

### انتخاب نوع مناسب

- برای «تعداد»، عدد صحیح انتخاب کنید؛ `2.5` عدد صحیح نیست.
- برای «وزن»، نوع اعشاری مناسب است.
- برای «کد ملی»، «کدپستی»، «تلفن» و «کد کالا»، متن مناسب‌تر است.
- برای تاریخ‌های واردشده از Excel، از سلول تاریخ استاندارد یا رشتهٔ میلادی قابل‌خواندن مانند `2026-10-13` استفاده کنید. تبدیل خودکار تاریخ شمسی تضمین نمی‌شود.
- انتخاب نوع `datetime` از فهرست داده، به‌تنهایی ابزار ترکیبی تاریخ و ساعت ایجاد نمی‌کند؛ ظاهر ورودی به ابزار انتخاب‌شده وابسته است.
- برای ورود عدد از Excel، از سلول عددی و ارقام انگلیسی استفاده کنید؛ تبدیل ارقام فارسی یا حذف جداکننده‌های دستی در همهٔ مسیرها تضمین نشده است.

## ۹. عرض، ترتیب و پیش‌نمایش فیلدها

### ۹.۱. عرض فیلد

فیلد را انتخاب کنید و در «عرض فیلد» یکی از گزینه‌ها را بزنید:

| گزینه | سهم از ردیف | کاربرد نمونه |
| --- | --- | --- |
| تمام ردیف | ۱۲ از ۱۲ ستون | توضیحات، آدرس |
| نصف ردیف | ۶ از ۱۲ ستون | نام و نام خانوادگی |
| یک‌سوم ردیف | ۴ از ۱۲ ستون | سه مقدار کوتاه |
| یک‌چهارم ردیف | ۳ از ۱۲ ستون | کد یا وضعیت کوتاه در دسکتاپ |

فیلدها از سمت راست ردیف چیده می‌شوند. مجموع عرضی که از ظرفیت ردیف بیشتر شود، به ردیف بعد می‌رود. تغییر عرض یا ترتیب، چیدمان را دوباره مرتب می‌کند؛ فاصله‌های خالی و جای‌گذاری آزاد پیکسلی هدف این طراح نیست.

### ۹.۲. تغییر ترتیب

- در دسکتاپ، دستگیرهٔ جابه‌جایی فیلد را بکشید؛
- یا از دکمه‌های «انتقال به قبل» و «انتقال به بعد» استفاده کنید؛
- در موبایل، از همین دکمه‌ها استفاده کنید؛ کشیدن فیلد غیرفعال است.

شمارهٔ بالای فیلد، ترتیب جاری آن را نشان می‌دهد. جابه‌جایی فیلدهای موجود، مقدار رکوردها را به فیلد دیگری منتقل نمی‌کند؛ شناسایی فیلدها مستقل از جایگاه نمایشی است.

### ۹.۳. پیش‌نمایش

«پیش‌نمایش» نمای کلی فرم، عنوان‌ها و مقدارهای اولیهٔ تعریف‌شده را نشان می‌دهد. ورودی‌ها و دکمهٔ «ثبت اطلاعات» در پیش‌نمایش غیرفعال‌اند؛ برای آزمایش ثبت واقعی باید فرم را ذخیره و صفحهٔ افزودن رکورد را باز کنید.

پیش‌نمایش، آزمون نهایی اعتبارسنجی، ارتباط‌ها یا مجوزها نیست. به‌ویژه لیست‌های مرتبط را بعد از ذخیره، در صفحهٔ ثبت رکورد آزمایش کنید.

<a id="field-settings"></a>
## ۱۰. تنظیمات پیشرفته و محدودیت‌ها

### ۱۰.۱. عنوان، نام و ضروری بودن

عنوان و نام انگلیسی هر فیلد را تکمیل کنید. اگر «وارد کردن این فیلد ضروری است» روشن باشد، سرویس مقدار خالی را رد می‌کند. در همهٔ صفحات، وجود ستاره کنار عنوان تضمین نمی‌شود؛ الزام اصلی هنگام ثبت اعمال می‌شود.

### ۱۰.۲. راهنما، متن داخل کادر و مقدار پیش‌فرض

این سه گزینه در بخش «متن راهنما و مقدار اولیه» قرار دارند:

| گزینه | منظور | وضعیت در نسخهٔ فعلی |
| --- | --- | --- |
| راهنمای فیلد | توضیح کوتاه برای کاربر | در تعریف و پیش‌نمایش قابل استفاده است؛ نمایش در فرم ورود واقعی کامل نیست |
| متن داخل کادر | نمونهٔ ورودی | در تعریف ذخیره می‌شود؛ نمایش در همهٔ ورودی‌های واقعی یکسان نیست |
| مقدار پیش‌فرض | مقدار اولیهٔ تعریف‌شده | در پیش‌نمایش دیده می‌شود؛ پر شدن خودکار صفحهٔ رکورد جدید تضمین نمی‌شود |

سرویس برای فیلدی که در درخواست ثبت اصلاً ارسال نشده باشد می‌تواند از مقدار پیش‌فرض استفاده کند؛ اما رابط فعلی معمولاً همهٔ فیلدها را ارسال می‌کند. برای استفادهٔ روزمره، مقدارهای لازم را هنگام ثبت بررسی و وارد کنید.

### ۱۰.۳. گزینه‌های بخش پیشرفته

| گزینه | اثر یا ملاحظه |
| --- | --- |
| قابل درج | سرویس اجازهٔ مقداردهی فیلد هنگام ایجاد رکورد را کنترل می‌کند |
| قابل ویرایش | سرویس تغییر مقدار فیلد در رکورد موجود را کنترل می‌کند |
| مقدار یکتا | مقدار غیرخالی تکراری در همان فرم رد می‌شود |
| بررسی تکرار | هنگام ایجاد رکورد، داده‌های مشابه برای تصمیم کاربر نمایش داده می‌شوند |
| مخفی در جدول | فیلد از خروجی Excel معمول کنار گذاشته می‌شود؛ جدول فعلی این پرچم را کامل اعمال نمی‌کند |
| نمایش در لیست انتخاب | در عنوان نمایشی رکوردهای این فرم در انتخاب‌گرها استفاده می‌شود |
| مخفی در فرم | در تعریف ذخیره می‌شود؛ رابط فعلی صفحهٔ رکورد آن را به‌طور کامل اعمال نمی‌کند |
| قابل جستجو | در تعریف ذخیره می‌شود؛ جستجوی فعلی به این پرچم برای محدود کردن دامنه متکی نیست |
| فعال | در تعریف ذخیره می‌شود؛ به‌تنهایی تضمین مسدودسازی فیلد نیست |
| محاسباتی | در نسخهٔ مستقل پشتیبانی نشده و ذخیرهٔ چنین تعریف‌هایی رد می‌شود |
| استایل CSS | در تعریف حفظ می‌شود؛ اجرای کامل آن در فرم رکورد فعلی تضمین نشده است |

گزینهٔ «مخفی» یا «قابل جستجو» ابزار حفاظت از اطلاعات محرمانه نیست. این نسخه نقش‌های دسترسی تفکیک‌شده ندارد. خاموش کردن «قابل درج» نیز لزوماً کادر را در رابط غیرفعال نمی‌کند؛ ممکن است کاربر بتواند مقدار وارد کند ولی سرویس ثبت را رد کند.

**تفاوت یکتا و بررسی تکرار:** یکتا بودن مانع قطعی ثبت مقدار تکراری است. بررسی تکرار، هشدار قابل عبور است. اگر چند فیلد حساس به تکرار باشند، رکورد مشابه با تطابق همهٔ آن فیلدهای دارای مقدار پیدا می‌شود. هشدار بررسی تکرار برای ایجاد رکورد است؛ به همان شکل برای ویرایش اجرا نمی‌شود.

### ۱۰.۴. عملیات فرم

بخش «عملیات فرم (اختیاری)» برای تعریف عملیات «دانلود»، «چاپ» یا عملیات سفارشی در رابط وجود دارد. در نسخهٔ مستقل فعلی، دکمه‌های این عملیات در فرم رکورد، اجرای متصل و کامل ندارند. آن‌ها را جایگزین دکمهٔ خروجی Excel یا چاپ مرورگر ندانید.

اسکریپت‌های سروری SQL، فیلدهای محاسباتی و قوانین اسکریپتی پشتیبانی نشده‌اند. برای ثبت معمول، همان «ثبت رکورد»، «ذخیره تغییرات» و «انصراف» کافی هستند.

<a id="lookups"></a>
## ۱۱. ساخت لیست‌های انتخاب

برای گزینه‌های محدود و ثابت، مانند «وضعیت مخاطب»، از لیست انتخاب استفاده کنید.

### ۱۱.۱. ساخت لیست

1. مسیر `/service/flow/lookup` را باز کنید و وارد ایجاد لیست شوید؛ یا مستقیماً `/service/flow/lookup/info` را باز کنید.
2. نوع «گزینه‌های مشخص» را انتخاب کنید.
3. عنوان «وضعیت مخاطب» را بنویسید.
4. با «افزودن ردیف»، گزینه‌ها را بسازید.
5. برای هر ردیف عنوان و مقدار وارد کنید.
6. «ذخیره» را بزنید و پیام موفقیت را بررسی کنید.

| عنوان گزینه | مقدار |
| --- | --- |
| فعال | `1` |
| غیرفعال | `2` |
| نیازمند پیگیری | `3` |

در رابط فعلی، مقدار گزینه باید عدد مثبت باشد. مقدارها را تکراری انتخاب نکنید. عنوان چیزی است که کاربر می‌بیند؛ مقدار شناسه‌ای است که ذخیره می‌شود.

ستون‌های توضیحات، رنگ و آیکن برای نگهداری اطلاعات نمایشی وجود دارند؛ نمایش همهٔ آن‌ها در انتخاب‌گرها تضمین نشده است. پیکان‌های ردیف برای تغییر ترتیب و دکمهٔ حذف برای حذف همان گزینه هستند.

### ۱۱.۲. اتصال لیست به فیلد

1. فرم مخاطبان را در طراح باز کنید.
2. فیلد «انتخاب» اضافه کنید.
3. عنوان «وضعیت»، نام `status` و نوع دادهٔ `int` را قرار دهید.
4. بخش «ارتباط با داده‌های دیگر» را باز کنید.
5. در «لیست انتخاب»، «وضعیت مخاطب» را انتخاب کنید.
6. برای این فیلد، فرم مرتبط را خالی نگه دارید.
7. فرم را ذخیره و در یک رکورد، انتخاب گزینه را آزمایش کنید.

برای چند انتخاب، ابزار «انتخاب چندگانه» و نوع دادهٔ رشته‌ای مناسب است. در یک فیلد، هم‌زمان لیست ثابت و ارتباط با فرم دیگر تنظیم نکنید.

### ۱۱.۳. تغییر لیست استفاده‌شده

اگر مقداری از یک گزینه در رکوردها استفاده شده باشد، حذف آن مقدار از لیست رد می‌شود. ابتدا رکوردهای استفاده‌کننده را اصلاح کنید. تغییر عنوان و حفظ مقدار معمولاً روش مناسب‌تری برای اصلاح نام گزینه است.

نوع «اسکریپت» در صفحه دیده می‌شود، اما در نسخهٔ مستقل فقط «گزینه‌های مشخص» پشتیبانی شده است.

<a id="relations"></a>
## ۱۲. ارتباط بین فرم‌ها

لیست انتخاب برای گزینهٔ ثابت است؛ ارتباط بین فرم‌ها برای گزینه‌ای مناسب است که خودش اطلاعات و رکورد دارد. مثال: مخاطب، شهر محل سکونت خود را از فرم «شهرها» انتخاب کند.

### ۱۲.۱. ساخت فرم مرجع

1. فرم «شهرها» با نام `cities` بسازید.
2. فیلد متنی «نام شهر» با نام `city_name` تعریف کنید.
3. در تنظیمات پیشرفتهٔ آن، «نمایش در لیست انتخاب» را روشن کنید.
4. در صورت نیاز، «مقدار یکتا» را روشن کنید تا نام شهر دوباره ثبت نشود.
5. فرم را ذخیره کنید.
6. رکوردهای «مشهد» و «تهران» را در آن ثبت کنید.

اگر هیچ فیلدی برای نمایش در لیست انتخاب مشخص نباشد، سرویس از اولین فیلد استفاده می‌کند. تعیین صریح فیلد نمایشی خوانایی انتخاب‌گر را بهتر می‌کند.

### ۱۲.۲. اتصال فرم اصلی

1. فرم مخاطبان را در طراح باز کنید.
2. یک فیلد «انتخاب» با عنوان «شهر» و نام `city_id` اضافه کنید.
3. برای رابطهٔ تک‌انتخابی، نوع `int` انتخاب کنید.
4. در «ارتباط با داده‌های دیگر»، فرم مرتبط را «شهرها» قرار دهید.
5. فیلد مرتبط را «نام شهر» انتخاب کنید.
6. لیست انتخاب ثابت را خالی نگه دارید.
7. فرم را ذخیره کنید.
8. در صفحهٔ رکورد، شهر را از انتخاب‌گر انتخاب کنید؛ عنوان شهر در جدول و Excel به‌صورت خوانا نمایش داده می‌شود.

این فیلد شناسهٔ رکورد شهر را نگهداری می‌کند، نه یک متن آزاد. برای ایجاد شهر تازه در ورود دستی، ابتدا رکورد آن را در فرم شهرها بسازید.

### ۱۲.۳. چند رابطه و حذف مرجع

برای انتخاب چند رکورد مرجع، از «انتخاب چندگانه» با نوع رشته‌ای استفاده کنید و همان فرم و فیلد مرتبط را تنظیم کنید.

رکوردی که در فرم دیگر به آن ارجاع شده است، قابل حذف نیست. ابتدا ارتباط رکوردهای وابسته را عوض یا پاک کنید. فرم مرجعی که تعریف فیلدهای دیگر به آن وابسته است نیز تا حذف یا اصلاح وابستگی قابل حذف نیست.

اگر فیلد شهرِ متنی قبلی داده دارد، آن را مستقیم به رابطه تبدیل نکنید؛ فیلد رابطهٔ جدید بسازید و داده‌ها را با بررسی منتقل کنید.

<a id="records"></a>
## ۱۳. ثبت، ویرایش و حذف رکوردها

### ۱۳.۱. ایجاد رکورد

1. از کارت فرم، «مشاهده رکوردها» را باز کنید.
2. «افزودن رکورد» را بزنید.
3. فیلدها را کامل کنید؛ در انتخاب‌گرها گزینهٔ موجود را انتخاب کنید.
4. «ثبت رکورد» را بزنید.
5. منتظر پیام موفقیت و پایان عملیات بمانید؛ سپس جدول را بررسی کنید.

اگر داده ناقص یا نامعتبر باشد، عملیات ثبت رد می‌شود. مهم‌ترین موارد: مقدار ضروری خالی، عدد نامعتبر، مقدار یکتا تکراری، گزینهٔ انتخابی ناموجود یا رابطهٔ نامعتبر.

دکمهٔ «انصراف» به جدول همان فرم می‌رود و تغییرات ذخیره‌نشده را ثبت نمی‌کند.

### ۱۳.۲. داده‌های مشابه

اگر بررسی تکرار در تعریف فیلدها روشن باشد، ممکن است پنجرهٔ داده‌های مشابه باز شود:

- اگر رکورد قبلاً ثبت شده است، انصراف دهید و همان رکورد را ویرایش کنید؛
- اگر مورد جدید واقعاً مستقل است، «ثبت با وجود تکرار» را بزنید.

این دکمه محدودیت «مقدار یکتا» را دور نمی‌زند. در فرم دارای یکتایی، مقدار تکراری همچنان رد می‌شود.

### ۱۳.۳. ویرایش

1. در جدول، آیکن مداد/ویرایش ردیف را بزنید.
2. مقدارها را تغییر دهید.
3. «ذخیره تغییرات» را بزنید.
4. جدول را بررسی کنید؛ در صورت نیاز «بروزرسانی» را بزنید.

تغییرات تنها بعد از ذخیره اعمال می‌شوند. خاموش بودن امکان ویرایش فرم یا فیلد، می‌تواند باعث رد درخواست شود حتی اگر کنترل ویرایش در رابط دیده شود.

### ۱۳.۴. حذف

1. آیکن سطل زبالهٔ ردیف را بزنید.
2. متن تأیید را بخوانید.
3. برای ادامه «حذف» یا برای صرف‌نظر «انصراف» را بزنید.

سطل زباله و بازیابی حذف در برنامه وجود ندارد. پس از حذف، بازگردانی فقط از پشتیبان مناسب ممکن است. حذف رکورد مرجع یا حذف از فرمی که اجازهٔ حذف ندارد، رد می‌شود.

<a id="search"></a>
## ۱۴. جستجو، مرتب‌سازی و صفحه‌بندی

### ۱۴.۱. جستجو داخل فرم

در بالای جدول، «جستجو در رکوردها» را پر کنید. جستجو با کمی تأخیر کوتاه انجام می‌شود. برای نمایش دوبارهٔ همهٔ موارد، عبارت را پاک کنید.

جستجوی فعلی از نوع یافتن عبارت در مقدارهاست؛ جستجوی هوشمند معنایی، اصلاح غلط املایی یا زبان پرس‌وجوی پیشرفته ندارد. یکسان‌سازی کامل «ی/ي»، «ک/ك»، نیم‌فاصله و ارقام فارسی/انگلیسی نیز تضمین نمی‌شود. اگر نتیجه پیدا نشد، عبارت کوتاه‌تر یا شکل دیگر نوشتن را امتحان کنید.

### ۱۴.۲. جستجو در همهٔ فرم‌ها

در داشبورد از «جستجو در داده‌ها» استفاده کنید. نتایج بر اساس فرم دسته‌بندی می‌شوند. سرویس در این مسیر حداکثر **۵۰ نتیجه از هر فرم** برمی‌گرداند؛ برای مرور همهٔ نتیجه‌ها، جدول همان فرم را باز کنید.

نبود نتیجه در یک عبارت، الزاماً به معنی نبود داده نیست؛ فیلترها، شکل نوشتن و فرم موردنظر را بررسی کنید.

### ۱۴.۳. مرتب‌سازی و صفحه‌بندی

- روی عنوان ستون قابل مرتب‌سازی کلیک کنید؛ ترتیب صعودی/نزولی از کنترل جدول مشخص می‌شود.
- از کنترل‌های پایین جدول برای صفحهٔ قبل/بعد و تعداد ردیف استفاده کنید.
- ترتیب پیش‌فرض سرویس، شناسهٔ رکورد نزولی است؛ رکورد جدیدتر معمولاً زودتر دیده می‌شود.
- «بروزرسانی» دادهٔ جدول را دوباره از سرویس می‌گیرد و برای تغییرات ثبت‌شده از مسیر دیگر مفید است.

شمارهٔ ردیف نمایشی را شناسهٔ دائمی رکورد ندانید؛ با تغییر صفحه یا ترتیب، جای رکورد در جدول عوض می‌شود.

<a id="excel-export"></a>
## ۱۵. خروجی Excel

1. جدول فرم را باز کنید.
2. اگر فقط بخشی از داده‌ها را می‌خواهید، جستجو را تنظیم کنید.
3. در صورت نیاز ترتیب ستون قابل مرتب‌سازی را انتخاب کنید.
4. آیکن «خروجی Excel» را بزنید.
5. فایل دانلودشده با نامی مانند `contactsReport.xlsx` را باز کنید.

خروجی شامل **همهٔ رکوردهای منطبق با فیلتر** است، نه فقط صفحهٔ جاری. برای خروجی کامل، ابتدا جستجو را پاک کنید. عنوان فارسی فیلدها سرستون می‌شود؛ فیلدهای علامت‌خورده با «مخفی در جدول» از خروجی معمول کنار گذاشته می‌شوند، هرچند جدول فعلی ممکن است همچنان آن‌ها را نمایش دهد. عنوان گزینه‌های لیست و رکوردهای مرتبط به‌صورت خوانا صادر می‌شود.

شیت خروجی راست‌به‌چپ است و ردیف عنوان ثابت می‌شود. فرمول، گزارش سفارشی، جمع‌بندی حسابداری و خروجی چندفرمی خودکار در این دکمه وجود ندارد.

**Excel پشتیبان کامل نیست:** تعریف فرم، حساب، نشست‌ها و همهٔ اطلاعات وابسته را دربرنمی‌گیرد. ورود دوبارهٔ فایل، رکوردهای موجود را به‌صورت خودکار به‌روزرسانی نمی‌کند و ممکن است رکورد تازه یا خطای تکرار ایجاد کند.

<a id="excel-import"></a>
## ۱۶. ورود اطلاعات از Excel

### ۱۶.۱. آماده‌سازی فایل

در نسخهٔ مستقل از فایل **`.xlsx`** استفاده کنید. متن قدیمی صفحه ممکن است `.xls` را هم ذکر کند، اما خوانندهٔ فعلی فایل xlsx می‌خواند؛ فایل xls را ابتدا در Excel یا نرم‌افزار سازگار به xlsx تبدیل کنید.

قواعد اصلی:

1. داده‌ها در **اولین شیت** باشند؛ شیت‌های بعدی خوانده نمی‌شوند.
2. ردیف اول، عنوان ستون‌ها باشد.
3. سرستون با عنوان فیلد یا نام انگلیسی آن مطابقت داشته باشد.
4. ستون یک فیلد را دوبار تکرار نکنید.
5. برای فیلدهای ضروری، مقدار معتبر بدهید.
6. فرمول‌ها را به مقدار ثابت تبدیل کنید؛ سلول فرمولی در ستون‌های خوانده‌شده پشتیبانی نمی‌شود.
7. حجم فایل حداکثر **۲۰ MiB** و تعداد ردیف داده حداکثر **۱۰٬۰۰۰** باشد؛ ردیف عنوان جدا از این سقف است.
8. شماره تلفن و کد دارای صفر ابتدایی را در Excel متن قرار دهید.

ستون نامنطبق خوانده نمی‌شود. اگر هیچ ستونی مطابقت نداشته باشد، فایل رد می‌شود. ردیف‌هایی که همهٔ ستون‌های منطبق آن‌ها خالی است کنار گذاشته می‌شوند. در تطبیق عنوان فارسی، فاصله‌ها حذف می‌شوند؛ با این حال بهتر است سرستون را دقیقاً از عنوان فرم کپی کنید.

در نسخهٔ فعلی، انگلیسی بودن نام شیت الزامی نیست؛ ملاک، اولین شیت بودن است. متن راهنمای قدیمی صفحه در این مورد با رفتار نسخهٔ مستقل متفاوت است.

### ۱۶.۲. نمونهٔ فایل مخاطبان

| نام کامل | تلفن | شهر | یادداشت |
| --- | --- | --- | --- |
| علی رضایی | `09151234567` | مشهد | پیگیری هفتهٔ آینده |
| مریم احمدی | `09121234567` | تهران | مشتری جدید |

می‌توانید به‌جای عنوان‌های فارسی، نام‌های `full_name`، `phone`، `city` و `notes` را در سرستون قرار دهید، اگر این نام‌ها دقیقاً نام فیلدهای فرم باشند.

### ۱۶.۳. بارگذاری و پیش‌نمایش

1. در جدول فرم، آیکن «ورود از Excel» را بزنید.
2. «انتخاب فایل» را بزنید و فایل xlsx را انتخاب کنید.
3. روی «آپلود» کلیک کنید.
4. پیش‌نمایش ردیف‌ها را بررسی کنید؛ در این مرحله، رکورد نهایی هنوز ثبت نشده است.
5. انتخاب ردیف‌ها را بررسی کنید؛ ردیف‌های پیش‌نمایش در حالت اولیه انتخاب‌شده هستند.
6. تیک موارد ناخواسته را بردارید. انتخاب همه/هیچ را از چک‌باکس سرستون جدول اصلی انجام دهید.
7. «ثبت» را بزنید.
8. بعد از پیام موفقیت، جدول فرم و چند رکورد نمونه را بررسی کنید.

«انصراف» مرحلهٔ پیش‌نمایش را کنار می‌گذارد. دکمهٔ ثبت تا انتخاب حداقل یک ردیف غیرفعال است.

### ۱۶.۴. لیست‌ها و روابط در Excel

- برای لیست ثابت، عنوان گزینه مانند «فعال» یا مقدار آن مانند `1` را وارد کنید.
- برای چند انتخاب، مقدارها را با ویرگول انگلیسی `,` جدا کنید.
- برای رابطهٔ فرم، مقدار فیلد نمایشی مرجع مانند «مشهد» را وارد کنید.
- اگر رکورد مرجع وجود داشته باشد، از آن استفاده می‌شود؛ اگر نباشد، یک رکورد مرجع در پیش‌نمایش برای ساخت آماده می‌شود.
- فقط وابستگی‌های ردیف‌های انتخاب‌شده همراه آن‌ها وارد می‌شوند؛ برداشتن تیک یک ردیف اصلی، به معنی ثبت شدن مستقل همهٔ وابستگی‌های نمایش‌داده‌شده نیست.

اگر فرم مرجع فیلد ضروری دیگری دارد که با مقدار پیش‌فرض یا دادهٔ واردشده تکمیل نمی‌شود، ساخت خودکار آن رکورد ممکن است شکست بخورد. در این حالت ابتدا رکوردهای مرجع را جداگانه بسازید و سپس فایل اصلی را وارد کنید. برای جلوگیری از انتخاب مبهم، مقدار فیلد مرجع را یکتا نگه دارید.

### ۱۶.۵. ثبت گروهی و تکرار

ورود Excel **ایجاد رکورد جدید** است؛ ویرایش گروهی رکوردهای قبلی بر اساس شناسه یا نام نیست. محدودیت‌های ضروری، نوع داده، یکتایی، روابط و قابلیت درج هنگام ثبت بررسی می‌شوند.

اگر یکی از ردیف‌های انتخاب‌شده نامعتبر باشد، ثبت گروهی در یک تراکنش رد می‌شود و ردیف‌های آن عملیات به‌صورت ناقص باقی نمی‌مانند. فایل را اصلاح و دوباره بارگذاری کنید. هشدار قابل‌عبور «بررسی تکرار» ورود دستی، در ورود گروهی همان پنجرهٔ تأیید را ندارد؛ یکتایی همچنان اعمال می‌شود.

پیش‌نمایش حداکثر **۸ ساعت** اعتبار دارد. اگر پس از پیش‌نمایش، تعریف فرم یا فرم‌های وابسته تغییر کند، ثبت رد می‌شود. فایل را دوباره بارگذاری کنید تا پیش‌نمایش تازه با تعریف جدید ساخته شود.

## ۱۷. تغییر فرم پس از ثبت اطلاعات

پیش از تغییر جدی ساختار، پشتیبان بگیرید.

| تغییر | رفتار و اقدام مناسب |
| --- | --- |
| تغییر عنوان فرم یا فیلد | معمولاً داده‌ها حفظ می‌شوند؛ سرستون Excel را برای ورودهای بعدی هماهنگ کنید |
| تغییر نام انگلیسی | برای همان فرم/فیلد موجود، شناسهٔ داخلی حفظ می‌شود؛ مسیرها و فایل‌های ورودی قبلی را بررسی کنید |
| تغییر عرض یا ترتیب | دادهٔ هر فیلد حفظ می‌شود؛ فرم رکورد بر اساس چیدمان جدید نمایش داده می‌شود |
| افزودن فیلد اختیاری | می‌تواند به فرم موجود اضافه شود؛ رکوردهای قدیمی را برای تکمیل بعدی بررسی کنید |
| افزودن/فعال کردن الزام ضروری | اگر رکوردهای قبلی الزام را نقض کنند، ذخیره رد می‌شود |
| فعال کردن یکتایی | اگر دادهٔ قبلی تکراری باشد، ذخیره رد می‌شود |
| تغییر نوع یا رابطهٔ فیلد دارای داده | برای جلوگیری از ناسازگاری، تغییرهای ناسازگار رد می‌شوند |
| حذف فیلد دارای مقدار | رد می‌شود؛ ساختار حاوی داده بی‌صدا حذف نمی‌شود |
| حذف فرم | رکوردهای آن فرم نیز حذف می‌شوند؛ فرم مرجع دارای وابستگی قابل حذف نیست |

برای تغییر مفهوم یک فیلد دارای داده، روش عملی معمولاً ساخت فیلد جدید، انتقال و بررسی داده‌ها و سپس تصمیم دربارهٔ فیلد قدیمی است. حذف فیلد و ساخت مجدد با همان نام را معادل تغییر نام ندانید؛ ممکن است شناسهٔ تازه‌ای ایجاد شود.

برای حذف فرم از فهرست مدیریتی `/service/flow/form` استفاده می‌شود. حذف فرم مخرب است و بازیابی داخلی ندارد؛ ابتدا پشتیبان بگیرید و وابستگی‌ها را بررسی کنید.

<a id="mobile"></a>
## ۱۸. کار با موبایل و صفحه‌کلید

### موبایل

- داشبورد کارت‌ها را به‌صورت تک‌ستونی نمایش می‌دهد.
- برای باز کردن منوی کناری، دکمهٔ منو را بزنید.
- در طراح، ابزارها، بوم و تنظیمات زیر هم قرار می‌گیرند.
- با انتخاب فیلد، صفحه به تنظیمات آن پیمایش می‌کند.
- فیلدهای طراح و پیش‌نمایش در صفحهٔ کوچک تمام‌عرض هستند؛ عرض انتخابی دسکتاپ در تعریف باقی می‌ماند.
- در فرم ثبت رکورد نیز فیلدها در صفحهٔ کوچک تمام‌عرض می‌شوند.
- جدول‌های عریض ممکن است به پیمایش افقی نیاز داشته باشند.

برای استفاده از گوشی در همان شبکه، بخش [دسترسی شبکه](#network) را ببینید. `127.0.0.1` روی گوشی به خود گوشی اشاره می‌کند، نه رایانهٔ اجراکننده.

### صفحه‌کلید

- با `Tab` و `Shift+Tab` میان کنترل‌ها حرکت کنید.
- در طراح، انتخاب‌گر تنظیمات فیلد با `Enter` یا کلید فاصله فعال می‌شود.
- از دکمه‌های انتقال به قبل/بعد برای ترتیب‌دهی بدون ماوس استفاده کنید.
- برای ذخیره، دکمهٔ مربوط را فعال کنید؛ میانبر اختصاصی `Ctrl+S` برای ذخیرهٔ فرم تعریف نشده است و ممکن است پنجرهٔ ذخیرهٔ صفحهٔ مرورگر را باز کند.

<a id="backup"></a>
## ۱۹. پشتیبان‌گیری، بازیابی و ارتقا

### ۱۹.۱. چه چیزی باید پشتیبان گرفته شود؟

اطلاعات داخل فایل اجرایی نیست. پشتیبان کامل، کپی **پوشهٔ اطلاعات** است که `flow.sqlite` و فایل‌های جانبی احتمالی SQLite را دربرمی‌گیرد. فایل اجرایی را می‌توانید دوباره دریافت کنید، اما دادهٔ شخصی فقط در پایگاه دادهٔ شماست.

### ۱۹.۲. پشتیبان کامل

1. کارهای ثبت و ویرایش را تمام کنید.
2. برنامه را با `Ctrl+C` متوقف کنید.
3. مطمئن شوید سرویس دیگری با همان پوشه اجرا نیست.
4. کل پوشهٔ اطلاعات را به محل جداگانه کپی کنید.
5. تاریخ و نسخهٔ برنامه را در نام یا یادداشت پشتیبان ثبت کنید.
6. نسخه‌ای از پشتیبان را روی رسانه یا رایانهٔ دیگر نگه دارید.
7. برنامه را دوباره با همان مسیر اصلی اجرا کنید.

هنگام اجرای سرویس، فقط `flow.sqlite` را کپی نکنید؛ تغییرات تازه ممکن است در `flow.sqlite-wal` باشند. روش این راهنما، کپی پس از توقف برنامه است.

مثال لینوکس، بعد از توقف و برای مسیر پیش‌فرض:

```sh
cp -a "$HOME/.local/share/flow" "$HOME/flow-backup-2026-10-13"
```

مثال PowerShell، بعد از توقف و برای مسیر صریح مثال‌های این راهنما:

```powershell
Copy-Item -Path 'C:\BunFlow\data' -Destination 'D:\Backups\BunFlow-2026-10-13' -Recurse
```

نام مقصد تازه و خالی انتخاب کنید. اگر مسیر اصلی شما متفاوت است، مثال را عیناً اجرا نکنید؛ مسیر واقعی را جایگزین کنید.

### ۱۹.۳. آزمایش بازیابی

به‌جای جایگزینی فوری اطلاعات اصلی، یک کپی از پشتیبان را در پوشهٔ آزمایشی بگذارید و با درگاه دیگر اجرا کنید:

```sh
./flow --data-dir /path/to/restored-copy --port 5001
```

یا در PowerShell:

```powershell
.\flow.exe --data-dir 'C:\BunFlow\restore-test' --port 5001
```

در `http://127.0.0.1:5001` با رمز همان پشتیبان وارد شوید و فرم‌ها، تعداد تقریبی رکوردها و چند رابطه را بررسی کنید. برای جایگزینی محیط اصلی، سرویس اصلی را متوقف کنید، پوشهٔ فعلی را جداگانه نگه دارید و سپس کپی تأییدشده را جایگزین کنید.

### ۱۹.۴. ارتقای فایل اجرایی

1. پشتیبان کامل بگیرید.
2. سرویس را متوقف کنید.
3. فایل اجرایی نسخهٔ تازه را دریافت و جایگزین کنید.
4. همان `--data-dir` قبلی را استفاده کنید.
5. در لینوکس در صورت نیاز دوباره `chmod +x flow` بزنید.
6. برنامه را اجرا کنید و ورود، جدول‌ها و چند رکورد را بررسی کنید.
7. اگر رابط قدیمی دیده می‌شود، صفحه را تازه‌سازی کامل کنید.

عدد نسخهٔ نمایش‌داده‌شده در رابط ممکن است با تگ انتشار یکسان نباشد؛ در کد فعلی چند مقدار نسخه ثابت هستند. برای تشخیص انتشار دانلودشده، تگ صفحهٔ Releases و نام پشتیبان را ملاک بگیرید. اعلان نسخهٔ جدید در رابط، جایگزین بررسی Releases نیست و سرویس فعلی بررسی به‌روزرسانی خودکار کامل ندارد.

<a id="network"></a>
## ۲۰. دسترسی در شبکهٔ محلی

اجرای پیش‌فرض فقط از همان رایانه قابل دسترسی است. برای استفادهٔ دستگاه دیگر در شبکهٔ محلی، برنامه را صریحاً روی رابط شبکه اجرا کنید:

```sh
./flow --host 0.0.0.0 --port 5000 --data-dir /path/to/flow-data
```

در ویندوز:

```powershell
.\flow.exe --host 0.0.0.0 --port 5000 --data-dir 'C:\BunFlow\data'
```

سپس در دستگاه دوم، نشانی IP واقعی رایانه را وارد کنید؛ مثلاً:

```text
http://192.168.1.20:5000
```

`0.0.0.0` نشانی قابل باز کردن در مرورگر نیست؛ نشانی گوش‌دادن سرویس است. ممکن است لازم باشد درگاه در فایروال برای شبکهٔ موردنظر مجاز شود.

این برنامه به‌صورت داخلی HTTPS ندارد. استفادهٔ پیش‌فرض محلی کم‌دردسرتر است. اگر آن را در شبکه یا اینترنت در دسترس می‌گذارید، رمز قوی، کنترل دسترسی شبکه و برای ارتباط امن، پراکسی HTTPS مناسب لازم است. باز کردن مستقیم درگاه روی اینترنت، سامانهٔ چندکاربره و مجوزهای تفکیک‌شده ایجاد نمی‌کند.

همهٔ مراجعه‌کنندگان از همان حساب مدیر و همان پایگاه داده استفاده می‌کنند. دو فایل اجرایی مستقل با پوشه‌های جدا، خودبه‌خود اطلاعات را همگام نمی‌کنند. برای اشتراک اطلاعات، دستگاه‌ها باید به یک سرویس مشترک وصل شوند؛ فایل SQLite فعال را در پوشهٔ همگام‌سازی یا پوشهٔ شبکه‌ای بین چند سرویس قرار ندهید.

## ۲۱. خطاهای رایج و راه‌حل‌ها

ممکن است بعضی پیام‌های سرویس به شکل کد انگلیسی نمایش داده شوند. جدول زیر معنی عملی آن‌ها را توضیح می‌دهد.

| نشانه یا کد | علت محتمل | اقدام |
| --- | --- | --- |
| صفحه باز نمی‌شود | سرویس اجرا نیست، نشانی/درگاه اشتباه است | ترمینال اجرا و `--port` را بررسی کنید |
| درگاه اشغال است | برنامه یا سرویس دیگری از درگاه استفاده می‌کند | اجرای اضافی را ببندید یا درگاه دیگر انتخاب کنید |
| `Permission denied` در لینوکس | فایل اجازهٔ اجرا ندارد | `chmod +x flow` اجرا کنید |
| `Exec format error` | فایل برای سیستم/معماری دیگری است | خروجی مناسب سیستم را دریافت کنید |
| نام کاربری یا رمز رد می‌شود / `invalid_credentials` | اطلاعات ورود نادرست است | `admin`، زبان صفحه‌کلید و رمز همان پایگاه داده را بررسی کنید |
| `password_must_have_8_characters` | رمز جدید کوتاه است | رمز حداقل ۸ نویسه وارد کنید |
| اطلاعات خالی شده به نظر می‌رسد | پوشهٔ اطلاعات دیگری باز شده است | مسیر اجرا و حساب سیستم‌عامل را بررسی کنید؛ فایل قبلی را حذف نکنید |
| ذخیرهٔ فرم رد می‌شود / `invalid_form_name_or_title` | عنوان خالی یا نام نامعتبر است | عنوان و قواعد نام انگلیسی را اصلاح کنید |
| `invalid_or_duplicate_field` | نام فیلد نامعتبر، تکراری یا رزروشده است | فیلدهای همان فرم را بررسی کنید |
| `form_name_exists` | نام انگلیسی فرم قبلاً استفاده شده است | نام متفاوت انتخاب کنید یا فرم موجود را ویرایش کنید |
| `required_field:...` | فیلد ضروری خالی است | مقدار فیلد ذکرشده را وارد کنید |
| `invalid_integer:...` / `invalid_number:...` | عدد نامعتبر است | عدد صحیح/اعشاری متناسب با نوع و بدون جداکنندهٔ دستی بدهید |
| `invalid_date:...` | تاریخ قابل خواندن نیست | تاریخ معتبر مرورگر یا قالب استاندارد میلادی استفاده کنید |
| `unique_field:...` | مقدار قبلاً وجود دارد | رکورد قبلی را پیدا یا مقدار تازه انتخاب کنید |
| `form_is_read_only` / `field_is_read_only:...` | مجوز درج/ویرایش/حذف خاموش است | تنظیمات فرم/فیلد را بررسی کنید |
| انتخاب‌گر خالی است | لیست/رابطه تنظیم نشده یا رکورد مرجع وجود ندارد | لیست، فرم مرتبط، فیلد مرتبط و رکوردهای مرجع را بررسی کنید |
| `invalid_lookup:...` / `unknown_lookup_label:...` | مقدار در لیست تعریف نشده است | عنوان یا مقدار دقیق گزینهٔ موجود را بدهید |
| `invalid_relation:...` | رکورد مرجع معتبر نیست | از انتخاب‌گر، رکورد موجود همان فرم مرجع را انتخاب کنید |
| `record_is_referenced` | رکورد در فرم دیگر استفاده شده است | ابتدا ارتباط رکوردهای وابسته را اصلاح کنید |

| `field_is_referenced` | تعریف فرم دیگری به فیلد ارجاع دارد | پیش از حذف، تعریف وابسته را اصلاح کنید |
| `field_has_data` | حذف فیلد دارای داده درخواست شده است | داده و پشتیبان را بررسی کنید؛ برای تغییر مفهوم، فیلد جدید بسازید |

| خطا در خواندن Excel / `could_not_read_excel_file` | xls، فایل خراب یا قالب نامعتبر است | فایل را به xlsx واقعی ذخیره و دوباره امتحان کنید |
| `no_matching_excel_columns` | سرستون با فیلدها تطبیق ندارد | عنوان یا نام انگلیسی دقیق فیلدها را در ردیف اول بگذارید |
| `duplicate_excel_column` | یک فیلد دوبار در سرستون آمده است | ستون تکراری را حذف کنید |
| `excel_formulas_not_supported` | سلول خوانده‌شده فرمول دارد | نتیجهٔ فرمول را با Paste Values جایگزین کنید |

| `excel_requires_1_to_10000_data_rows` | فایل خالی یا بیش از سقف ردیف است | اولین شیت و تعداد ردیف‌ها را اصلاح کنید |
| `import_preview_expired` | بیش از مهلت پیش‌نمایش گذشته است | فایل را دوباره بارگذاری کنید |
| `form_changed_since_import_preview` | تعریف فرم/وابستگی تغییر کرده است | پیش‌نمایش تازه بسازید |
| `only_option_lookups_supported` | لیست اسکریپتی درخواست شده است | نوع گزینه‌های مشخص را انتخاب کنید |
| `computed_fields_and_script_rules_need_migration` | فیلد محاسباتی/قانون اسکریپتی فعال است | برای نسخهٔ مستقل، این قابلیت را کنار بگذارید |
| `server_sql_actions_need_migration` | عملیات SQL سفارشی تعریف شده است | از عملیات معمول نسخهٔ مستقل استفاده کنید |
| `endpoint_not_supported_by_standalone` | صفحه/قابلیت قدیمی به سرویس پیاده‌نشده متکی است | بخش محدودیت‌ها را ببینید |

### وقتی ذخیره موفق نشده است

فرم یا رکورد را صرفاً با کلیک روی دکمه، ذخیره‌شده فرض نکنید. پیام موفقیت و وجود داده در جدول را بررسی کنید. اگر جدول در حالت انتظار مانده است، نشانی را ثبت کنید، صفحه را دوباره باز کنید و لاگ ترمینال را بررسی کنید؛ پیش از تکرار ثبت، مطمئن شوید رکورد قبلی ایجاد نشده باشد.

### گزارش مشکل

برای نگهدارندهٔ برنامه، این اطلاعات را فراهم کنید: سیستم‌عامل و معماری، تگ انتشار، نام صفحه، گام‌های بازتولید، متن کامل خطا و نمونهٔ غیرحساس از فایل مشکل‌دار. رمز عبور، توکن ورود یا کل پایگاه دادهٔ واقعی را در گزارش عمومی منتشر نکنید.

<a id="json-transfer"></a>
## ۲۳. پیوست: انتقال تعریف فرم‌ها و داده با JSON

این بخش برای کاربر فنی یا مدیر سیستم است. دکمهٔ اختصاصی انتقال ساختار در رابط وجود ندارد. برای استفادهٔ معمول، Excel و پشتیبان پوشه کافی‌اند.

| روش | مسیر | کاربرد |
| --- | --- | --- |
| `POST` | `/api/identity/account/token` | دریافت توکن ورود |
| `GET` | `/api/flow/schema/export` | خروجی تعریف فرم‌ها و لیست‌ها |
| `GET` | `/api/flow/schema/export?includeData=true` | خروجی تعریف‌ها، لیست‌ها و رکوردها |
| `POST` | `/api/flow/schema/import` | وارد کردن بستهٔ JSON |

برای احراز هویت، بدنهٔ ورود به این شکل است؛ رمز نمونه را جایگزین کنید و آن را منتشر نکنید:

```json
{"username":"admin","password":"YOUR_PASSWORD","type":1}
```

توکن در `result.accessToken` پاسخ قرار دارد. در درخواست‌های بعدی، سرآیند زیر را بفرستید:

```text
Authorization: Bearer YOUR_ACCESS_TOKEN
```

### نمونهٔ PowerShell

نمونهٔ زیر رمز را با ورودی پوشیده دریافت می‌کند و خروجی کامل را در فایل UTF-8 ذخیره می‌کند. رمز نمونهٔ ثابت داخل کد ندارد:

```powershell
$baseUrl = 'http://127.0.0.1:5000'
$credential = Get-Credential -UserName 'admin' -Message 'BunFlow local login'
$loginBody = @{
  username = $credential.UserName
  password = $credential.GetNetworkCredential().Password
  type = 1
} | ConvertTo-Json
$loginResult = Invoke-RestMethod -Method Post -Uri "$baseUrl/api/identity/account/token" -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($loginBody))
$authHeaders = @{ Authorization = "Bearer $($loginResult.result.accessToken)" }
Invoke-WebRequest -UseBasicParsing -Uri "$baseUrl/api/flow/schema/export?includeData=true" -Headers $authHeaders -OutFile '.\flow-export.json'
Remove-Variable credential, loginBody, loginResult
```

برای خروجی بدون رکورد، قسمت `?includeData=true` را حذف کنید. برای وارد کردن فایل در **فضای کاری مقصد مناسب**:

```powershell
$bundleText = Get-Content -LiteralPath '.\flow-export.json' -Raw -Encoding UTF8
$bundleBytes = [System.Text.Encoding]::UTF8.GetBytes($bundleText)
Invoke-RestMethod -Method Post -Uri "$baseUrl/api/flow/schema/import" -Headers $authHeaders -ContentType 'application/json; charset=utf-8' -Body $bundleBytes
Remove-Variable authHeaders, bundleText, bundleBytes
```

اگر مقصد روی درگاه یا رایانهٔ دیگری است، `$baseUrl` را تغییر دهید و **برای همان مقصد** توکن تازه بگیرید. درخواست ورود/وارد کردن را به فضای کاری واقعی فقط وقتی بفرستید که مقصد را بررسی کرده‌اید.

### محدودیت‌های انتقال JSON

- بسته باید قالب خروجی همین نسخهٔ مستقل را داشته باشد؛ JSON دلخواه یا خروجی تاریخی نسخهٔ قدیمی قابل تضمین نیست.
- وارد کردن، فرم‌های جدید می‌سازد؛ نام فرم موجود باعث تعارض می‌شود.
- دادهٔ موجود با این عملیات بازنویسی یا ادغام خودکار نمی‌شود.
- شناسهٔ فرم‌ها، فیلدها و رکوردها بازنگاشت می‌شود تا روابط داخلی بسته حفظ شود.
- بایت فایل‌های بارگذاری‌شده، حساب کاربران، نشست‌ها و زمان‌های اصلی ثبت/ویرایش رکورد در بستهٔ داده پوشش کامل ندارند.
- برای انتقال با API، اندازهٔ کل درخواست نیز محدود است؛ سرویس سقف بدنهٔ درخواست ۲۵ MiB دارد.
- این خروجی جایگزین پشتیبان کامل پوشهٔ پایگاه داده نیست.

## ۲۴. چک‌لیست‌ها و واژه‌نامه

### پیش از انتشار یک فرم برای استفادهٔ واقعی

- [ ] عنوان، نام انگلیسی و توضیحات روشن‌اند.
- [ ] تلفن و کد دارای صفر ابتدایی، متنی هستند.
- [ ] فیلدهای ضروری واقعاً ضروری‌اند.
- [ ] لیست‌ها و روابط در یک رکورد آزمایشی درست کار می‌کنند.
- [ ] عرض و ترتیب در دسکتاپ و موبایل بررسی شده‌اند.
- [ ] پیش‌نمایش و ذخیرهٔ فرم انجام شده‌اند.
- [ ] یک ثبت و ویرایش واقعی موفق بوده است.
- [ ] خروجی Excel و ورود نمونهٔ کوچک بررسی شده‌اند.
- [ ] مسیر پوشهٔ اطلاعات و روش پشتیبان‌گیری مشخص است.

### استفادهٔ روزمره

- [ ] برنامه با همان پوشهٔ اطلاعات درست اجرا شده است.
- [ ] برای پیدا کردن رکورد، جستجوی مناسب انتخاب شده است.
- [ ] بعد از ثبت/ویرایش، نتیجه در جدول بررسی شده است.
- [ ] پیش از حذف یا تغییر ساختار، پشتیبان گرفته شده است.
- [ ] پیش از ورود گروهی، پیش‌نمایش و تعداد انتخاب‌ها بررسی شده‌اند.
- [ ] پیش از گرفتن خروجی کامل، جستجوی جدول پاک شده است.
- [ ] پشتیبان دوره‌ای و یک آزمایش بازیابی انجام شده است.

### واژه‌نامهٔ کوتاه

| واژه | معادل و توضیح |
| --- | --- |
| Standalone | مستقل؛ یک فایل اجرایی سرویس و رابط را اجرا می‌کند |
| SQLite | پایگاه دادهٔ محلی برنامه در فایل |
| Data directory | پوشهٔ اطلاعات که با `--data-dir` تعیین می‌شود |
| Lookup | لیست گزینه‌های ثابت |
| Relation | ارتباط فیلد با رکورد یک فرم دیگر |
| Schema | تعریف ساختار فرم‌ها و فیلدها |
| Unique | یکتا؛ مقدار تکراری پذیرفته نمی‌شود |
| Preview | پیش‌نمایش؛ بررسی پیش از ذخیره/ثبت نهایی |
| Transaction | ثبت یکپارچه؛ در شکست عملیات گروهی، ثبت ناقص باقی نمی‌ماند |
| WAL | فایل جانبی SQLite که ممکن است تغییرات تازه در آن باشد |
| Token | شناسهٔ احراز هویت API؛ مانند رمز باید محافظت شود |
| Release tag | تگ انتشار در GitHub برای مشخص کردن یک نسخهٔ کد |
